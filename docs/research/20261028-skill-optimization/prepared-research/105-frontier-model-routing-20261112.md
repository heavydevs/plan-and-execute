# P055 — Fresh model catalog and sixth frontier capability tier
**Research baseline:** 2026-11-12 (current vendor documentation), **status:** architecture decision only, not dispatched or benchmark-validated.
**Scope:** extend existing adaptive routing and model catalog, not a new routing engine or permanent marketing-label lookup.

## Observed discrepancy
The checkpoint routingctl.py declares five canonical tiers: economy/L1, standard/L2, advanced/L3, strong/L4, max/L5. Its 2026-10-09 defaults still mention Claude Fable 5.1 at max, Claude Sonnet/Opus 5.5, and Codex GPT-6.1 Sol (not Astra at max), as a prior local preference. MODEL_MAPPING.md last reviewed 2026-10-27. Providers and quota pools are independently routed in workload_routing, availability and catalog modules. These entries are not a current universal ranking.

## Current official facts (check model IDs at implementation time)

Mythos 5.2 is verification-gated, NOT generally selectable. Fable 5.1 remains active but no longer the newest; no guessing retirement.
- OpenAI: GPT-6 Astra ID gpt-6-astra is official flagship for most demanding work, reasoning.effort low/medium/high/xhigh/max; API standard input $10/output $50 per million. GPT-6.1 Sol ID gpt-6.1-sol provides near-Astra performance at $2/$10, same effort vocabulary. Luna cost-sensitive and Terra may supply additional middle price points, subject to resolved CLI/account listing. Do not conflate API rates with subscription Codex credits; ChatGPT UI availability differs from Codex CLI/API.
- Google Antigravity CLI model examples explicitly list gemini-4-carbon-high/medium/low and gemini-4-argon-high/medium; Google launched Carbon on November 10, 2026 for demanding long-horizon/software coordination and Argon for broader engineering. Carbon availability is Google AI Ultra/eligible Enterprise; Argon is paid Pro/Ultra/Enterprise. Native CLI list agy models is decisive; ID includes effort, do not send a conflicting duplicate --effort flag. Antigravity lists Claude Opus 5.5 but NOT Claude Fable 5.2 or GPT-6 Astra in the public matrix; do not manufacture cross-host IDs or bypass the pre-existing conservative Antigravity Claude advanced cap without explicit tested policy change. Antigravity CLI tool soft-denial can exit zero: acceptance requires tool/output checks.
- Other families/adapters (Qwen Code, Kimi, GLM, DeepSeek, Muse, Trae) may be mapped only with documented exact installed/model IDs, actual reasoning options, availability and reproduction benchmarks. No fictitious equality by brand, provider or parameter count. If there is no proven sixth-tier candidate, report unavailable and choose explicit escalation/approval policy rather than silently pretending a lower-tier model is frontier.
- Vendor claims and benchmark leaderboards are not head-to-head measurements for this repository. OpenAI itself flags contamination of older SWE-bench Verified results; prefer fresh representative real-task replay and blinded independent acceptance.

## Chosen design: L6/F6 = frontier (new canonical tier ABOVE max)
- Preserve existing five-tier semantics and stable aliases L1–L5/F1–F5. Add only frontier, aliases L6 and F6, new opt-in capability signals e.g. frontier_critical_reasoning, repeated_max_failure after classified evidence. Do not route ordinary expensive long parent requests into frontier: classify semantic leaf, blast radius, confidence, validation strength, retry history; L6 only when L5 is inadequate, risk of undetected failure is extraordinary or explicit user override.
- Proposed candidates for qualified L6 at baseline: Claude Code claude-fable-5-2 with effort high/xhigh/max as actually CLI-supported; Codex gpt-6-astra high/xhigh/max; Google Antigravity gemini-4-carbon-high (only if agy models actually lists it and quota/profile eligible). Gemini 4 Argon High is normally L5 candidate, not automatically L6 equal to Carbon. Claude Opus 5.5 and GPT-6.1 Sol are retained at <=L5. Avoid assigning all L6 models equivalent cost/quality without evals.
- Refresh the COMPLETE provider/model mapping across economy, standard, advanced, strong, max, frontier at the implementation date. Audit every provider-specific adapter and workload overlay, coding vs design vs diagnostics vs planner/reviewer, native effort values, paid API/subscription quota pools, provider-scope auth, feature flags and prices; record unknown/not observed explicitly. Only update snapshots for future/pending tasks; ongoing task attempt binding stays immutable. Existing user override/config remains authoritative and legacy persisted L1–L5 plans must still execute under old policy unless explicitly migrated.
- Determine allowed models via versioned observed CLI account catalog, authoritative vendor docs and capability evidence, independently expired price/availability/effort facets. No fictitious model IDs, promotion of unverified unavailable endpoints, silently treating unknown cost as zero, unapproved API billing, or accidental override of user provider restrictions. Cross-provider execution remains only on hosts authorized for actual implementation; a model appearing in public docs does not grant agent/CLI credentials.
- For L6 hard jobs, prefer a single high-quality architect/reviewer on an isolated bounded evidence packet. Escalate from max to frontier only on confirmed semantic/cross-cutting failure or user-selected critical work; no frontier on environment fault, quota or stalled runner. Budget per verified solved outcome: include token cash price, subscription credits, latency, review, rework and failed retries. If unsupported, offer status/other provider selection with no silent downgrade below floor.
- Compatibility plan: TIER_ORDER/normalize_tier, schemas/validators (manifest schema-v4, task contracts, candidate selectors, cost tables, escalation ladders, effort caps), provider-specific adapters and observed-model lists, profile import/export, docs, README, automated tests. Preserve the v5 logical max values when L6 disabled, golden argv snapshots and old configs. New feature enablement via explicit config or policy migration, NOT in the middle of an active worker.

## Acceptance and evaluation
1. Unit/property tests of all 6 tiers, F/L aliases, monotonic floors, multiple providers/quotas, preview explanations, effort ID composition, unknown/unavailable frontier.
2. With L6 disabled, identical route/argv/selection for legacy L1–L5 frozen fixtures and in-progress checkpoints; no invisible Fable/Astra charge.
3. With enabled observed IDs: high-risk classified leaf can choose Fable 5.2/Astra/Carbon High; known cheaper eligible equal-tier alternatives are compared by validated cost; no provider UI-name-based inference.
4. Recovery of invalid-model and account quota failures preserves provider pool and refresh bounds, never transforms environment outage into premium escalation. Regression: Antigravity soft exit zero does not count as successful completion.
5. Comparative blinded tests: representative architecture, cross-cutting migration, subtle debugging, security, frontend and functional validation tasks, minimum acceptance rubric, sample size and replay harness; compare Sol vs Astra, Opus vs Fable, Argon vs Carbon where actually permitted. Vendor marketing does not establish a winner. Report quality per completed/validated task, credits, walltime, confidence intervals/uncertainty and no-results when provider unavailable.
6. Independent maximum-qualified review 106 records exact reviewed source hashes, cost/warnings and corrections; integration 082/086 includes matrix test + changed docs/release notes.
