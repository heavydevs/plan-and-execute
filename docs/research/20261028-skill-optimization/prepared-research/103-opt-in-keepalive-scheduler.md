# P054 — Optional twenty-minute self-recovery scheduler tied to plan lifecycle
**Research baseline:** 2026-11-12. **Status:** engineering design only; unimplemented; independent review required.
**Scope:** augment the existing keepalivectl.py / watchdogctl.py and integrate lifecycle. Do NOT introduce a second orchestrator, paid poller or separate installed skill.

## Existing repository evidence (checked on named checkpoint branch)
- skill/plan-and-execute/scripts/keepalivectl.py: already detects runner_dead, awaiting_next and quota_resume_due and relaunches using leases, a short-lived lock, a 3-per-180-minute restart budget; Windows scheduled task XML and manual POSIX cron print exist.
- skill/plan-and-execute/scripts/watchdogctl.py remains read-only, distinguishes silent live work, blocked, permission, failed validation, quota and dead runner; 5–10-minute observations already documented.
- references/WATCHDOG.md already recommends a 20-minute keepalive check. Missing: automatic conditional opt-in, POSIX scheduler installation with ownership/cleanup, terminal lifecycle cleanup, exact host checks.
- Existing TODO 091/092 repairs complex product blockers; 099/100 handle semantic lack of progress; 101/102 hold one native power inhibitor for the whole RUNNING plan. Never duplicate those mechanisms.

## Decision and tradeoffs
**Trigger:** offer the scheduler once per new interactive local ORCHESTRATED plan only when there are >=6 genuinely pending executable TODOs at enrollment; exclude DIRECT, completed and archived tasks. Count independent review TODOs if they are actual required execution gates. Six is an intentionally conservative gate: 4–5 short tasks rarely amortize OS scheduling complexity and can complete before the first 20-minute check, whereas >=6 offers a plausible overnight/multi-session benefit. This is a policy heuristic, not an empirically optimized threshold; emit count and allow future configuration after measured evaluation. After a plan is enrolled, do not disable its timer merely because remaining tasks drop below six.
**Authorization:** ask just once: enable automatic local recovery every 20 minutes until plan termination? Default no on an unanswered/noninteractive session; explicit opt-in flag for unattended creation, explicit opt-out; store only policy + plan-scoped key, never raw prompt histories. Re-running initialization/resume never nags or silently registers OS jobs.
**Scope:** one host-owned scheduled status/keepalive tick per plan, not a conversational ChatGPT reminder. Only local installed CLI agent, configured credentials and authorized permissions can be resumed; hosted/GUI chat sessions cannot be restarted by cron. Show one actionable status message if unavailable.
**Algorithm:** at each tick, inspect authoritative manifest, plan identity, host, live runner lease, ownership, active selection and cooldowns without generative calls. If live runner or active validation exists, never terminate it; silent progress invokes 099 diagnostic, not a blind restart. Restart only runner_dead, awaiting_next or quota_resume_due when runnable and not paused/blocked/awaiting human. Respect max three restart launches per rolling 180 minutes (or conservative configured policy), atomic mutex + lease, cooldown windows and flags. Invalid/partial state must fail closed. No extra charge while healthy; possible additional provider credits only for authenticated actual resumed work and retries.
**OS backend:** Windows Task Scheduler per-plan XML with MultipleInstancesPolicy=IgnoreNew, no elevated privileges, no persistent wake-on-battery by default, current-user identity and absolute resolved interpreter/repo paths; pause/remove via exact owned task. On Linux prefer a per-user systemd .timer/.service pair, OnActiveSec=20min and OnUnitActiveSec=20min with short accuracy; if user manager unavailable, user crontab with exact owned sentinel and atomic preservation of unrelated entries ONLY after explicit confirmation/capability check. Explicitly diagnose session logout/linger and do not run loginctl enable-linger without separate authorization. macOS: equivalent per-user launchd LaunchAgent StartInterval=1200 with explicit label/ownership if supported; otherwise transparent unsupported. Avoid a second wake-capable scheduler in WSL: a Linux guest timer cannot guarantee the Windows physical host; host-side opt-in separately or report degradation.
**Cleanup:** success/failed-terminal/cancel/reset/explicit unenroll must uninstall the matching scheduler registration BEFORE destructive plan cleanup; power lease (TODO 101) is released on completion, pause and termination independently. Keep a tiny OS scheduler ownership record outside disposable plan directory until uninstall verified. If forced crash removes plan directory, the next tick detects terminal/missing plan and safely self-unregisters, or surfaces actionable cleanup failure; no orphaned recurring ticks. Use unique plan UUID + repo fingerprint + expected OS job name, checked ownership; never delete other plans' entries or user crontabs. Add deterministic retry cleanup and a read-only list/health CLI; simulate corrupted/missing plan, manual scheduler deletion, shared hosts, symlinks, concurrent plans, idempotent uninstall and end-boundary failures. Windows DeleteExpiredTaskAfter is only a backup when trigger end boundary is set, NOT the primary lifecycle cleanup.
**Power:** a scheduler checks every 20 minutes but does NOT continuously inhibit OS idle sleep, does NOT keep a dead runner's lease alive, and does NOT guarantee waking a suspended machine. The host-owned native inhibitor in TODO 101/102 is acquired before any RUNNING worker and released at plan terminal or pause; after recovery it is reacquired before provider dispatch. Never force system-wide powercfg, pmset, logind.conf, lid override, injected keypress or administrative policy. On Windows, Modern Standby/DC can limit requests; on Linux lid events commonly ignore high-level inhibition. Timer removal and inhibitor release are separate atomic/compensated finalizers.
**Subskill decision:** reject a second installed skill: it would duplicate lifecycle authority, policy, packaging and model context. Implement small optional deterministic OS adapters under scripts/ and reference only when installing/uninstalling; no AI worker/subskill per timer event.

## Test contract
- Gate at 0,3,4,5,6,7 initial unfinished TODOs, then 5 after a prior opt-in; exactly one offer; noninteractive never prompts or installs; opt-out/no permissions leaves no OS artifact.
- Exercise mocked Windows Task Scheduler, systemd user timer, cron fallback, launchd where supported, WSL distinction, dry-run, idempotent install/remove, concurrent plans, shell quoting, hostile paths, symlink and interrupted registration.
- Simulated 20-minute tick: live runner remains running; dead + runnable resumes once; blocked/permission/failed job/ongoing meaningful validation are not restarted; quota only after due; third subsequent crash locks recovery; stale pid not treated as live.
- Crash cleanup: terminal plan deletes timer + owned state; a deleted plan or power outage leaves a self-removing/diagnosed scheduler, never an endless orphan.
- Integrate TODOs 091,099,101 contracts; final npm/CI checks must include new test. Hold all changes pending genuine fresh review 104, then integration 082 and review 086.
- Emit compact one-line scheduling status, no secrets, no model invocation from healthy ticks. Record actual native-platform results; mocks are not physical overnight proof.
