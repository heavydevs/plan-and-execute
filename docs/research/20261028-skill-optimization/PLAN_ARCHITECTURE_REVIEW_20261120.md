## Decisions made while applying (review dispatch)

Defect: review task 003 (max tier) ran on Claude Opus 5.5 xhigh in a headless `claude -p` worker. It launched the required reviewer as a background agent, and the turn ended before that agent returned. The Claude envelope showed `stop_reason: tool_use` and `subagent_stats` with `started_in_background: 1`, `completed: 0` and `killed.system: 1`. That attempt cost US$3.54, over 8 attempts in total. The Codex attempts failed with "workspace is out of credits" (availability). Every review task has the same S002 wording, so the fault would recur, and the repeated `mechanical` failures at the top rung would feed the frontier counter (`frontier.enabled: true, min_top_failures: 2`).

- R1. **Helper.** `support/review_dispatch.py --repo-root . --task <NNN> [--brief <file>] [--input <path>] [--dry-run] [--new] [--wait-seconds N]`. It is plan-support code next to `run_task_checks.py` and imports `check_delivery` and the runner's own builders.
- R2. **Route.** `routing_config.provider_chain(task, config, tier="max")` reads the plan's `tier_routes.max` (Codex, then Claude). The model is the provider's configured `max` model, passed through `resolve_snapshot_route`. The effort is the task effort with an xhigh floor, clamped by `max_effort_by_tier` (Sol 6.2 xhigh / Opus 5.5 xhigh). The helper skips:
  - providers with an active cooldown in `results/<task>-availability.json` (`workload_routing.cooldown_keys`);
  - missing CLIs;
  - adapters without a pinned read-only review argv. Antigravity's summary argv carries `--dangerously-skip-permissions`;
  - frontier model ids.
  `routingctl.select_route` is not used. It ranks catalog candidates by cost and ignores the plan's configured chain and models, while the runner's own dispatch binds the plan through `tier_routes`. Frontier is never chosen here; the existing gate rules still apply to any frontier receipt.
- R3. **Read-only argv.** The argv is `run_isolated.build_summary_command`, the adapter-pinned read-only command used for summaries, switched to structured JSON:
  - Claude: `--permission-mode plan --output-format json --tools Read,Grep,Glob --json-schema`. The tool list also stops a nested reviewer from spawning background agents.
  - Codex: `exec --ephemeral --sandbox read-only --json --output-schema`.
  - `extra_args` are filtered first. The live Codex config carries `--dangerously-bypass-approvals-and-sandbox`, which is dropped. The helper fails closed (exit 3) unless the final argv provably holds `plan` or `read-only` and no `--dangerously-*` or full-access token.
- R4. **Synchronous but resumable.** Claude Code 2.1.322 moves a foreground Bash command that is still running at its timeout to the background. The cap is 600 s by default (`BASH_MAX_TIMEOUT_MS`), so a single long blocking call would recreate the defect. The helper therefore runs the reviewer under a small wrapper process. The wrapper owns the provider process tree through `process_tree` and writes a heartbeat file. Each call:
  - waits in the foreground for at most `--wait-seconds` (default 540);
  - if the reviewer is still running, prints `PENDING` and exits 75. Running the same command again resumes waiting on the same reviewer, with no second spend.
  - Edge cases:
    - The worker never relies on a notification.
    - If the worker exits anyway, the runner's job object ends the tree. A heartbeat older than 60 s marks that dispatch abandoned, and the next call starts a new one.
    - Different inputs while a reviewer is still running return exit 4 unless `--abandon-pending` is given.
- R5. **Availability.** A failed call is classified with `availability.classify`. Quota, auth, capacity, configured-exit and missing-CLI faults call `availability.unavailable(..., phase="implementation")`, which cools that provider down for this task, and the helper tries the next provider. The ledger only knows the design and implementation phases, and the review dispatch runs inside the implementation phase. Other failures also move to the next provider, without a cooldown: configuration, nonzero exit, no session id, invalid output. Nothing touches the task's failure counters. Exit 2 means no provider could review.
- R6. **Evidence.** Each dispatch writes `implementation/reviews/<id>/brief-<n>.md`, `findings-<n>.json` and `dispatch-<n>.json`.
  - `dispatch-<n>.json` records task id, review_of, provider, model, native_effort, requested_effort, `model_tier=max`, fresh_context, read_only, session_id, observed models, brief path and LF-text sha256, reviewed-input hashes, redacted argv, timestamps, exit code, usage, verdict, finding counts, findings path and sha256, and the skipped attempts.
  - Files are written once (`x` mode), with the platform newline, like `run_task_checks.py`.
  - Raw stdout/stderr and the wrapper state stay in the gitignored `.ai-work/<plan>/reviews/<id>/`, so transcripts never enter the evidence.
  - A model without an effort flag (Haiku) records `native_effort: default`.
  - The helper prints:
    - `DISPATCH task= session= evidence= sha256=`;
    - the compact findings, at most 4000 bytes;
    - a `RECEIPT_REVIEWER {json}` line with the exact `reviewer` and `reviewed_inputs` blocks for the receipt.
- R7. **Reviewed inputs and gate fit.** The reviewed inputs are the predecessor's receipt and outcome, plus the changed or preserved artifacts that receipt pins (current hashes), plus any `--input`. A receipt that pins them satisfies `check_delivery.check`:
  - the evidence names the pinned hashes;
  - the previous output and report are pinned.
  A correction changes a hash, which changes the brief and forces a fresh dispatch on the final state. `check_delivery.py` is unchanged, so no validator was weakened.
- R8. **Reuse.** The helper refuses (exit 3) when:
  - a returned session already appears in any dispatch file or in another receipt (`reviewer` plus `prior_max_failures`, via `used_dispatches`);
  - a call is nested inside a reviewer (`PAE_REVIEW_DISPATCH_ACTIVE`).
  An identical brief (same task, same reviewed hashes) reprints the existing dispatch without a spend; `--new` forces a second opinion.
